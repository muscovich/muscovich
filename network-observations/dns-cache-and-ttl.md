# DNS Cache Behaviour and TTL Expiration

**Level:** Intermediate  
**Estimated time:** 35-45 minutes  
**Focus:** DNS caching, TTL, Python UDP sockets, monotonic time, packet analysis

## 1. Learning objective

Extend the local DNS lab by implementing a small client-side DNS cache. Observe how a cache can answer repeated lookups without sending another DNS query, and how an expired entry causes a new query.

This is a controlled teaching cache, not a replacement for an operating-system or production DNS resolver.

## 2. Concepts to understand

- DNS resource-record TTL
- Positive caching and cache hits/misses
- Cache expiration
- Monotonic clocks versus wall-clock time
- DNS transaction IDs
- UDP query/response exchanges
- Why cached answers may not generate packets on the network

## 3. Legal and safe lab scope

Use only your own Linux machine or a VM you control. Reuse the local DNS responder from `dns-protocol-analysis.md`, bound to `127.0.0.1:53535`. All DNS traffic remains on loopback. Do not point the lab at public resolvers or third-party systems.

## 4. Required tools

- Linux or a Linux VM
- Python 3
- Wireshark or tcpdump
- The `dns_server.py` responder from the previous DNS exercise

### Step 2 - Create a cache-aware client

Create `dns_cache_client.py`:

```python
import socket
import struct
import time
import random

SERVER = ("127.0.0.1", 53535)
CACHE = {}

def encode_name(name):
    encoded = b""
    for label in name.split("."):
        part = label.encode("ascii")
        if not part or len(part) > 63:
            raise ValueError("Invalid DNS label")
        encoded += bytes([len(part)]) + part
    return encoded + b"\\x00"

def query_dns(name):
    txid = random.randrange(65536)
    header = struct.pack("!HHHHHH", txid, 0x0100, 1, 0, 0, 0)
    question = encode_name(name) + struct.pack("!HH", 1, 1)
    packet = header + question

    with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as sock:
        sock.settimeout(3)
        sock.sendto(packet, SERVER)
        response, _ = sock.recvfrom(512)

    if len(response) < 12 or len(response) < 12 + len(question) + 16:
        raise ValueError("Incomplete DNS response")

    rid, flags, qdcount, ancount, _, _ = struct.unpack("!HHHHHH", response[:12])
    if rid != txid or not (flags & 0x8000) or ancount < 1:
        raise ValueError("Unexpected DNS response")

    answer_offset = 12 + len(question)
    rtype, rclass, ttl, rdlength = struct.unpack(
        "!HHIH", response[answer_offset + 2:answer_offset + 12]
    )
    if rtype != 1 or rclass != 1 or rdlength != 4:
        raise ValueError("Expected one IPv4 A record")

    address = socket.inet_ntoa(response[answer_offset + 12:answer_offset + 16])
    return address, ttl

def resolve(name):
    now = time.monotonic()
    cached = CACHE.get(name)

    if cached and now < cached["expires"]:
        remaining = int(cached["expires"] - now)
        print(f"CACHE HIT: {name} -> {cached['address']} ({remaining}s remain)")
        return cached["address"]

    if cached:
        print(f"CACHE EXPIRED: {name}")

    print(f"CACHE MISS: querying local DNS responder for {name}")
    address, ttl = query_dns(name)

    if ttl > 0:
        CACHE[name] = {
            "address": address,
            "expires": time.monotonic() + ttl
        }

    print(f"DNS RESPONSE: {name} -> {address}, TTL={ttl}s")
    return address

if __name__ == "__main__":
    name = "cache-lab.example"

    resolve(name)
    time.sleep(2)
    resolve(name)
    print("Waiting for the 10-second TTL to expire...")
    time.sleep(9)
    resolve(name)
```

The client uses `time.monotonic()` to measure expiration. A monotonic clock is appropriate for elapsed-time calculations because it is not affected by wall-clock adjustments.

This parser is deliberately limited to the fixed, single A-record response generated by the teaching responder. It is not a general DNS parser.

### Step 3 - Capture the exchange

In a second terminal, start a capture:

Stop tcpdump with Ctrl+C after the client finishes.

### Step 4 - Inspect the packet capture

Open `dns-cache-lab.pcap` in Wireshark and use:

| Investigation | Display filter |
|---|---|
| DNS packets | `dns` |
| Queries only | `dns.flags.response == 0` |
| Responses only | `dns.flags.response == 1` |
| Lab UDP traffic | `udp.port == 53535` |

Compare the number of cache messages printed by the client with the number of DNS query/response pairs in the capture.

Expected behaviour: the first lookup should require a network query, the second lookup should be served from the unexpired cache, and the lookup after expiration should query the responder again. Verify this from your own output and capture.

## 7. Knowledge assessment

1. What does a DNS TTL represent?
2. Why does a cache use an expiration time rather than retaining an answer indefinitely?
3. Why is a monotonic clock suitable for measuring cache lifetime?
4. Why might a cache hit produce no DNS packet on the loopback interface?
5. Does a TTL of 10 seconds guarantee that every DNS cache in a real system will retain an answer for exactly 10 seconds? Explain.
6. What could happen if a DNS record changes while a client still has an unexpired cached answer?
7. How would negative caching differ from the positive A-record cache in this exercise?
8. Why is this teaching cache not a complete recursive resolver?
