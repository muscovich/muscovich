# Week 01 - TCP Handshake and Network Traffic Analysis

**Level:** Intermediate  
**Estimated time:** 45-60 minutes  
**Focus:** TCP, DNS, packet capture, Wireshark, Linux networking, Python

## 1. Learning objective

Capture traffic generated by your own computer and investigate how DNS resolution and TCP connection establishment work. Identify the TCP three-way handshake, inspect connection termination, and use Python to extract basic statistics from a PCAP file.

The aim is to explain what the packets demonstrate, not just identify protocol names.

## 2. Concepts to understand

- TCP: reliable, connection-oriented transport.
- UDP: connectionless transport.
- SYN, ACK, FIN, and RST: TCP control flags.
- TCP three-way handshake: SYN, SYN-ACK, ACK.
- DNS: hostname resolution.
- Source and destination ports.
- Packet capture and the PCAP file format.
- Directional flows versus bidirectional conversations.

## 3. Legal and safe lab scope

Use only your own computer, your own network interface, and traffic that you generate yourself. Do not capture or inspect other people's traffic. Do not test systems or networks without explicit permission. The commands below generate ordinary DNS and HTTPS requests; they do not attempt to access or disrupt remote services.

## 4. Required tools

- Linux terminal or WSL2.
- tcpdump.
- Wireshark.
- Python 3.
- Scapy Python package.

Official downloads and documentation are linked in the references section.

## 5. Practical investigation

### Step 1 - Identify your network configuration

Run:

```bash
ip addr
ip route
```

Identify your active interface, local IPv4 address, default gateway, and default route. Keep private network details out of public notes.

### Step 2 - Inspect DNS resolution

Run:

```bash
dig example.com
```

If `dig` is unavailable, use:

```bash
nslookup example.com
```

Record the resolver shown, query type, returned address records, and query duration if displayed. Consider why a client normally needs to resolve a hostname before connecting to a server by name.

### Step 3 - Capture traffic generated by your computer

Start a capture on your own interface:

```bash
sudo tcpdump -i any -nn -s 0 -w week01-network.pcap
```

While the capture runs, open another terminal and generate a DNS query and HTTPS request:

```bash
dig example.com
curl -I https://example.com
```

Stop the capture with Ctrl+C after both commands finish. The capture may contain other traffic from your own computer, so avoid doing unrelated activity during the capture.

### Step 4 - Inspect packets in Wireshark

Open the capture:

```bash
wireshark week01-network.pcap
```

Try these display filters:

| Display filter | Purpose |
| --- | --- |
| `tcp` | TCP packets |
| `udp` | UDP packets |
| `dns` | DNS traffic |
| `tcp.flags.syn == 1` | Packets with SYN set |
| `tcp.flags.ack == 1` | Packets with ACK set |
| `tcp.flags.fin == 1` | Packets with FIN set |
| `tcp.flags.reset == 1` | Packets with RST set |
| `tcp.port == 443` | TCP traffic using port 443 |

Find a TCP connection associated with your HTTPS request. If the full handshake was captured, identify SYN, SYN-ACK, and ACK in sequence. Then inspect later packets and look for FIN or RST. The handshake or teardown may be missing if capture began late, ended early, or the connection was reused.

For a candidate connection, note the source and destination IP addresses and ports. Use Follow TCP Stream if useful, but remember that HTTPS application data is encrypted.

### Step 5 - Analyse the PCAP with Python

Create and activate a virtual environment, then install Scapy:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install scapy
```

Save the following as `tcp_analysis.py` in the same directory as the capture:

```python
from collections import Counter
from scapy.all import rdpcap, IP, TCP

packets = rdpcap("week01-network.pcap")

flag_counts = Counter()
directional_flows = set()
tcp_packet_count = 0

for packet in packets:
    if IP not in packet or TCP not in packet:
        continue

    tcp_packet_count += 1
    tcp = packet[TCP]
    flags = int(tcp.flags)

    if flags & 0x02:
        flag_counts["SYN"] += 1
    if flags & 0x10:
        flag_counts["ACK"] += 1
    if flags & 0x01:
        flag_counts["FIN"] += 1
    if flags & 0x04:
        flag_counts["RST"] += 1

    directional_flows.add((
        packet[IP].src,
        tcp.sport,
        packet[IP].dst,
        tcp.dport
    ))

print("Total captured packets:", len(packets))
print("TCP packets:", tcp_packet_count)
print("Unique directional 4-tuples:", len(directional_flows))

for flag, count in sorted(flag_counts.items()):
    print(f"{flag} packets: {count}")
```

Run:

```bash
python tcp_analysis.py
```

Interpret the script carefully. It counts packets containing each flag, not unique connections. A packet can contain multiple flags. The 4-tuple set is directional, so the reverse direction is counted separately. It is not a count of unique TCP conversations or successful handshakes.

## 7. Knowledge assessment

Answer in your own words:

1. Why does TCP use a three-way handshake?
2. What might happen if a SYN-ACK never reaches the client?
3. How does TCP differ from UDP?
4. Why is DNS commonly carried over UDP, and can DNS use TCP?
5. What does a TCP RST indicate?
6. Why can a capture show HTTPS packets without revealing the webpage contents?
7. What is the difference between a TCP packet and a TCP connection?
8. Why is counting SYN packets not the same as counting successful connections?

**Challenge:** If repeated SYN packets appear without a corresponding SYN-ACK, list at least three possible explanations. Consider packet loss, routing, filtering, service state, and capture location before deciding what the trace proves.
